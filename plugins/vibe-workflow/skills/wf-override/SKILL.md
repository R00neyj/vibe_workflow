# wf-override — 게이트 한시 해제

`WFCTL` = `node "${CLAUDE_PLUGIN_ROOT}/scripts/wfctl.js"`

## 먼저 확인할 것

우회는 **마지막 수단이다.** 요청받으면 먼저 정규 경로가 정말 막혔는지 확인한다.

| 상황 | 우회 대신 |
| --- | --- |
| 계획 미승인 | `/wf-review` 로 승인받기 (보통 1분이면 끝난다) |
| 계획에 없는 파일 | plan.md 의 `files` 수정 후 재승인 |
| 오타·주석 같은 사소한 수정 | 그래도 짧은 task 를 만드는 편이 낫다 |
| 프로덕션 장애 대응 | 우회가 맞다 |
| 무엇을 만들지 탐색 중 | 우회가 맞다 |

사용자가 정규 경로를 듣고도 우회를 원하면 그대로 진행한다. 설득을 반복하지 마라.

## 실행

```
WFCTL override <분> "<사유>"
```

- 분은 1~480 범위. **필요한 만큼만 짧게** 연다. 기본 제안은 30분.
- 사유는 필수다. `.workflow/gate.log` 에 기록된다.

우회 중에는 소스 쓰기가 전부 허용되고, 각 쓰기가 로그에 남는다.

## 반드시 닫기

작업이 끝나면 즉시:

```
WFCTL override-clear
```

만료 시각이 지나면 자동으로 무효가 되지만, 열어둔 채로 두지 마라.

## 사후 처리

우회로 코드를 고쳤다면 그 변경은 계획·검증을 거치지 않은 상태다. 사용자에게 다음을 제안한다.

- 무엇을 고쳤는지 `backlog.yaml` 에 사후 기록
- 임시 수정이면 정식 task 로 다시 다룰 항목 추가
- 우회 중 변경 목록은 `.workflow/gate.log` 의 `OVERRIDE` 행에서 확인
